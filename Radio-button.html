Radio Button

A Radio Group presents a set of mutually exclusive options where users can select exactly one. It wraps individual Radio Button items under a shared group label, optional help text, and coordinated validation states.

Anatomy

The Radio Group is composed of a group label, individual radio buttons, and optional help text.

Content GuidelinesRecommended

Do
  • Use a concise group label that frames the decision.
  • Always pre-select a sensible default when one exists.
  • Keep option labels to 1–4 words.
  • Group semantically related options together.
  • Show an error state + help text together.
Don't
  • Leave the group unlabelled.
  • Leave all options unselected if a default makes sense.
  • Write full sentences as radio labels.
  • Mix unrelated options in a single group.
  • Show only a red border without explaining what went wrong.

When and Where to Use

Radio groups let users choose exactly one option from a small, visible set of mutually exclusive choices.

When to use

  • When the user must choose exactly one option from a small, finite list (2–6 options).
  • When all options need to be visible at once without interaction.
  • For settings or configuration screens where the full set of choices is informative.

When NOT to use

  • Multiple selections — use Checkbox Group.
  • Long lists (7+) — use Select Box to save vertical space.
  • Binary yes/no with immediate effect — use Toggle.
  • Yes/No inside a form — a single Checkbox may suffice.

Layout Guidance

Choose the right layout based on available space and label length.

LayoutDefault?Description
LeftYes (web)Options are laid out horizontally in a row. Default for all standard responsive web layouts.
TopSpecial caseOptions stack vertically below the group label. Use only when horizontal space is severely constrained, for mobile viewports, or when options have long labels that wrap.

Complete Do's and Don'ts

Guidelines for effective radio button usage.

Do
  • Concise group label: Frame the decision clearly with a short group label.
  • Pre-select a default: Always pre-select a sensible default when one exists.
  • Use Left layout: Use the default Left layout for standard web forms.
  • Error + help text: Show an error state and help text together.
  • Short labels: Keep option labels to 1–4 words.
  • Semantic grouping: Group semantically related options together.
Don't
  • No unlabelled groups: Don't leave the group unlabelled.
  • No empty selection: Don't leave all options unselected if a default makes sense.
  • Avoid Top layout: Switch to Top layout only when labels are very long or horizontal space is unavailable.
  • No red-only errors: Don't show only a red border without explaining what went wrong.
  • No full sentences: Don't write full sentences as radio labels.
  • No mixed groups: Don't mix unrelated options in a single group.

RTL Support

  • Control and label swap sides automatically when dir="rtl" is set on a parent element.
  • The rtl prop on RadioGroup applies right-to-left layout to all child items.
  • Individual RadioButton items can override the group's direction via their own rtl prop.

Accessibility

Guidelines for ensuring radio button groups are accessible across assistive technologies.

Keyboard Interaction

KeyAction
TabMoves focus into the radio group (to the selected or first option).
Arrow Up / LeftMoves focus and selection to the previous radio option.
Arrow Down / RightMoves focus and selection to the next radio option.
SpaceSelects the currently focused radio option.

Tab moves focus into the group; Arrow keys move between options; Space selects the focused option. Focus wraps within the group.

ARIA Attributes & Screen Reader Guidance

  • ARIA role: Wrap with <fieldset> + <legend> (or role="radiogroup" + aria-labelledby).
  • Screen reader: Each option reads as: "[Label], radio button, [N] of [total], [group label]".
  • Error state: Associate help text via aria-describedby on the group or on each input.
  • Disabled state: Set disabled attribute on <input type="radio">; do not use aria-disabled alone.
  • RTL: Control and label swap sides automatically; dir="rtl" on a parent element is sufficient.

Focus State Design

  • Focus ring uses Border/Border-Accent-Focus token — must remain visible and not rely on colour alone.
  • Focus is visible as a 3px ring around the radio control circle.
  • When a radio option receives focus, it is also selected (following the standard radio group pattern).
