Content GuidelinesRecommended

Do
  • Keep navigation labels concise and recognizable (1–2 words).
  • Use the correct variant for the product's navigation architecture.
  • Always show the active tab state so users know where they are.
  • Turn off unused Nav slots to prevent empty spacing in the tab row.
Don't
  • Use long multi-word labels that cause tab overflow prematurely.
  • Use the Endpoint Central variant in a left-nav product or vice versa.
  • Leave all tabs in the inactive state — users lose wayfinding context.
  • Hide search purely for visual tidiness — it is a core utility.

When and Where to Use

The Header Navigation is the primary persistent chrome for every product page.

When to use

  • As the single persistent top bar for every page in a product.
  • Use Endpoint Central when the product has top-level horizontal navigation (8 items or fewer).
  • Use the left-nav variants (EC left only, MDM, Patch Manager Plus) when primary navigation is in a left sidebar.

When NOT to use

  • As a secondary navigation bar within a page — use Tabs or a Section Header instead.
  • Inside a modal or flyout — navigation is not needed inside overlay contexts.
  • As a mobile top bar — this component is designed for desktop/1440px viewports.

Alignment & Placement

Consistent placement ensures predictable navigation across all products.

  • Position: Always fixed at the top of the viewport. The header persists across all page scrolls.
  • Width: Full viewport width (1440px design, stretches to container).
  • Z-index: Above all page content. Modals and drawers may overlay the header.
  • Logo zone: Always at the far left. The product icon and name are not interactive beyond acting as a home link.
  • Utility cluster: Always at the far right. Icon order is consistent across all variants.

Complete Do's and Don'ts

Guidelines for effective header navigation usage.

Do
  • Match the variant to the product: Use Endpoint Central for top-nav products, left-nav variants for sidebar products.
  • Keep Nav slot count accurate: Turn off unused Nav N props to avoid empty spacing.
  • Show Customer Selector for multi-tenant: It allows switching between tenants/accounts.
  • Set the correct active tab: Coordinate with the current page to show the right active state.
  • Keep search visible: Only use Show Search=OFF when search is genuinely unavailable.
Don't
  • Don't leave unused Nav slots ON: They create empty spacing in the tab row.
  • Don't mix navigation architectures: Using Endpoint Central in a left-nav product creates confusion.
  • Don't show Customer Selector in single-tenant: It is unnecessary for personal-account products.
  • Don't leave all tabs inactive: Users lose wayfinding context without an active indicator.
  • Don't hide search for aesthetics: Search is a core utility expected by users.

RTL Support

  • In RTL layouts, the logo zone moves to the far right and the utility cluster to the far left. Tab order is reversed visually.
  • The search bar placeholder text and ⌘K hint badge align correctly in RTL via the dir="rtl" attribute on the header or page root.
  • Icon-only utility buttons (Search, Settings, Notifications, etc.) are direction-neutral and require no mirroring.
  • The Customer Selector chevron direction should flip to indicate dropdown direction in RTL contexts.

Accessibility

Guidelines for ensuring the Header Navigation is accessible across assistive technologies.

Keyboard Interaction

KeyAction
TabMoves focus through interactive elements: logo (home link), nav tabs, utility buttons, avatar.
Shift+TabMoves focus backward through the header's interactive elements.
EnterActivates the focused tab link, utility button, or opens the customer selector dropdown.
EscapeCloses the overflow menu (⋯) or customer selector dropdown if open.

Provide a visually hidden "Skip to main content" link before the header so keyboard users can bypass the full navigation.

ARIA Attributes & Screen Reader Guidance

  • Landmark: Wrap the header in <header role="banner"> for proper landmark identification.
  • Nav landmark: The tab group must be in <nav aria-label="Primary navigation">.
  • Active tab: The active tab link gets aria-current="page".
  • Icon-only buttons: Settings, Notifications, Bookmark, Link, Bento, and Search icons must each have aria-label describing their purpose.
  • Customer Selector: Must use aria-haspopup="listbox" and aria-expanded on the trigger.
  • Overflow menu: The ⋯ button needs aria-label="More navigation items" and aria-expanded toggled.
  • Avatar: Must have aria-label="User menu"; opens a dropdown when activated.
  • Skip link: Provide a visually hidden "Skip to main content" link before the header for keyboard users.

Focus State Design

  • All interactive items (tabs, utility buttons, avatar, customer selector) must have a visible :focus-visible outline.
  • Use a 2px offset focus ring in Brand Blue (#0C66E4) or the system default for high visibility against the white header background.
  • Focus order should follow the visual layout: Logo → Nav tabs / Search → Utility cluster (left to right).
