Status Indicator

The Status Indicator displays system states, health conditions, or operational statuses using a colored dot, optional icon, and optional text label.

Content GuidelinesRecommended

Do
  • Use consistent status-to-color mapping throughout the app.
  • Always include text label when status meaning isn't obvious.
  • Use Small for dense layouts (tables, lists).
  • Use semantic statuses consistently (Neutral=idle, Success=online, Warning=degraded, Critical=error, Info=informational).
Don't
  • Don't use more than 5 status types in a single view.
  • Don't rely solely on dot color -- always include label for accessibility.
  • Don't use for numeric counts (use Counter).
  • Don't mix sizes within same table column.

When and Where to Use

The Status Indicator communicates system or record state at a glance using color and text.

When to use

  • Record status in tables (e.g., Active, Inactive, Pending).
  • Connection or availability status (e.g., Online, Offline).
  • Workflow state indicators (e.g., Draft, Published, Archived).
  • System health in dashboards (e.g., Healthy, Degraded, Down).
  • Process status in lists (e.g., Running, Paused, Complete).

When NOT to use

  • For numeric counts -- use Counter instead.
  • For category labels -- use Badge or Tag instead.
  • For non-interactive decoration without a label.

Semantic States

Each status carries a specific semantic meaning. Use them consistently across your application.

  • Neutral: Inactive, idle, unknown -- used when status is indeterminate or not yet set.
  • Success: Healthy, online, completed -- positive states indicating normal operation.
  • Warning: Degraded, at-risk, attention needed -- caution states that may require intervention.
  • Critical: Error, offline, failed, urgent -- negative states requiring immediate attention.
  • Info: Informational, in-progress, active -- neutral-positive states for ongoing operations.

Complete Do's and Don'ts

Visual and interaction guidelines to ensure Status Indicators are effective and accessible.

Do
  • Consistent mapping: Use the same status-to-color mapping throughout the entire application.
  • Include labels: Always include a text label when the meaning isn't obvious from context.
  • Dense layouts: Use Small size for data tables and lists where space is limited.
  • Semantic consistency: Neutral=idle, Success=online, Warning=degraded, Critical=error, Info=informational.
Don't
  • Too many types: Don't use more than 5 status types in a single view.
  • Color-only: Don't rely solely on dot color -- always include a label for accessibility.
  • Wrong component: Don't use for numeric counts (use Counter) or categories (use Badge/Tag).
  • Inconsistent sizing: Don't mix sizes within the same table column or list.

Layout

The Status Indicator uses a simple horizontal auto-layout container.

  • Layout: Horizontal auto-layout
  • Alignment: Center vertical alignment
  • Sizing: Hugs content (width and height)
  • Corner Radius: 6px
  • Item Spacing: 4px gap between dot, icon, and label
  • Padding: 4px on all sides

Accessibility

Guidelines for ensuring Status Indicators are accessible to all users and assistive technologies.

Accessibility Guidelines

GuidelineRequirementDetails
LabelAlways show text labelAlways show text label for screen readers. If the label is visually hidden, use aria-label or sr-only class.
ContrastWCAG AA compliantAll dot colors meet WCAG AA contrast requirements against white backgrounds.
Color IndependenceText label requiredText label communicates meaning -- the dot color is supplementary, not the sole indicator.
Screen ReaderAnnounced as label textThe status is announced as its label text (e.g., "Online", "Offline"). Add role="status" for live updates.
KeyboardFocusable if interactiveIf the Status Indicator is interactive, it must be focusable via Tab with a visible focus ring.

Color ContrastWCAG AA Pass

All status dot colors have been verified to meet WCAG 2.1 Level AA contrast requirements.

WCAG 2.1 Level AA: All five dot colors (Neutral #5F6C89, Success #0C8844, Warning #E65100, Critical #C1181B, Info #2C66DD) meet the minimum 3.0:1 contrast ratio for UI components against white backgrounds. Text labels use #2A303D which exceeds the 4.5:1 requirement for normal text.

Best Practices

  • Never rely solely on color to communicate status -- always pair with a text label.
  • Use role="status" and aria-live="polite" for status indicators that update dynamically.
  • If the indicator is inside a table cell, ensure the cell has an accessible header describing the column purpose.
  • For icon-only variants (Show Label = false), always provide an aria-label with the status text.
