Tag

The Tag is a compact, interactive label component used to categorize, filter, or represent metadata that users can act upon. Tags support dismissal (close), leading elements (icons or status indicators), and multiple semantic color variants.

Content GuidelinesRecommended

Do
  • Use tags for user-generated or user-selectable labels (filters, categories, selections).
  • Keep label text short (1-3 words).
  • Use Show Close for dismissible tags in multi-select fields or filter bars.
  • Use consistent semantic variants across the application for the same meaning.
  • Use the Outline variant when tags appear over colored or patterned backgrounds.
  • Use Status Indicator as the leading element to combine status communication with labeling.
Don't
  • Don't use tags for non-interactive status display (use Badge instead).
  • Don't use more than 2-3 words in a tag label.
  • Don't mix semantic variant colors arbitrarily within the same context.
  • Don't disable the close button while keeping the tag interactive; disable the entire tag instead.
  • Don't use tags as primary navigation elements.

Style

Design tokens, color mappings, and sizing specifications that define the Tag's visual language.

Variant Axes

The Tag component is built from five independent variant axes, producing a comprehensive matrix of 432 unique combinations.

  • Variant: 6 options — Neutral, Primary, Success, Warning, Error, Outline
  • Size: 3 options — Small, Medium, Large
  • State: 4 options — Default, Hover, Focus, Disabled
  • RTL: 2 options — False, True
  • Leading Element: 3 options — None, Status Indicator, Icon
  • Total: 6 × 3 × 4 × 2 × 3 = 432 variants

Semantic Variants

Each variant communicates a distinct semantic meaning through its color palette. Filled variants use a tinted background with darker text; the Outline variant uses a transparent background with a visible border.

VariantHueUsage
NeutralGreyGeneral-purpose, no specific semantic meaning.
PrimaryBlueActive selections, primary categorization.
SuccessGreenPositive or confirmed status tags.
WarningAmber/OrangeTags requiring attention or caution.

OutlineGrey (border)Low-emphasis tags on colored or busy backgrounds.

When to Use

Tags are best suited for compact, interactive labels that users can add, remove, or filter by.

  • Categorization: Label items with categories such as department, type, or priority.
  • Filtering: Represent active filter selections in search bars or filter panels.
  • Metadata: Display metadata values like status, owner, or version inline with content.
  • Multi-select inputs: Show selected values as dismissible tags inside combo boxes or multi-select fields.

Leading Element

Tags support an optional leading element to add visual context before the label text.

TypeDescription
NoneNo leading element. Only label and optional close button.
Status IndicatorA small colored dot before the label. Useful for showing inline status.
IconA swappable icon before the label. Useful for adding visual context.

RTL Support

The Tag component fully supports right-to-left languages with automatic layout mirroring.

  • Layout direction: Mirrored — leading element moves to trailing, close button to leading.
  • Text alignment: Adjusted to follow natural RTL reading order.
  • Spacing and padding: Mirrored to maintain consistent visual balance.
  • RTL Label property: Uses the dedicated RTL Label text property for localized content.

Instance Overrides

Steps to customize a Tag instance in your design tool or codebase.

  • 1. Select the Tag instance.
  • 2. Toggle Show Close on/off.
  • 3. Edit the Label text directly.
  • 4. Change Leading Element variant to add icon or status indicator.
  • 5. Swap the Leading Icon or Status Indicator.
  • 6. Toggle RTL for right-to-left language support.

Accessibility

Guidelines for ensuring all tag interactions are accessible across assistive technologies.

Color ContrastWCAG AA Pass

All filled tag variants meet WCAG 2.1 AA contrast ratio requirements (4.5:1 for text). The tinted background and darker foreground text combination ensures legibility across all semantic variants.

WCAG 2.1 Level AA: All UEMS Tag variants use tinted backgrounds with high-contrast foreground text, meeting the minimum 4.5:1 contrast ratio for normal text.

Keyboard Navigation

Tags and their close buttons are fully keyboard accessible.

  • Tab: Tags are focusable via the Tab key, allowing keyboard users to navigate to them.
  • Close button focus: The close button is independently focusable, so users can dismiss a tag without affecting adjacent elements.
  • Focus indicator: A visible focus ring is displayed around the tag or close button when focused.

Screen Reader

Ensure tag content and actions are properly announced to screen readers.

  • Label text: The tag label is read as text content by screen readers.
  • Close button: The close button should have an accessible label such as "Remove [tag name]" to clearly communicate its purpose.

RTL Accessibility

  • Full RTL support with mirrored layout ensures the tag reads naturally in right-to-left languages.
  • The localized RTL Label property provides proper text content for assistive technologies in RTL contexts.

Disabled State

  • Disabled tags are excluded from the tab order, preventing keyboard users from focusing on non-interactive elements.
  • The disabled state is conveyed to assistive technology via aria-disabled="true", ensuring screen readers communicate the inactive state.
