Illustrations

Use illustrations to guide action, explain complex workflows, and reduce uncertainty across endpoint management experiences.

In Prism, illustrations are functional visual aids. They help clarify empty states, explain deployment workflows, support onboarding, reinforce AI guidance, and humanize error recovery.

A strong illustration system improves comprehension without increasing cognitive load in dense enterprise environments.

Why illustrations matter in endpoint products

Endpoint workflows often include:

  • Empty device groups
  • First-time onboarding
  • Failed patch states
  • Threat remediation guidance
  • AI-generated workflow explanations
  • Policy setup walkthroughs
  • Remote troubleshooting steps
  • Success confirmations
  • Upgrade and migration announcements

Without a clear illustration system, these moments become text-heavy, emotionally flat, and harder to act on.

A strong illustration foundation improves:

  • Better task comprehension
  • Faster first-use learning
  • Reduced empty-state confusion
  • Better AI explanation UX
  • Stronger product warmth
  • Better enterprise brand recall

Illustrations must support the workflow -- not distract from it.

Illustration types

Prism supports three in-product illustration types.

Spot illustrations
One clear concept or outcome. Empty states, success moments, error recovery.
Low-fi workflow UI
Complex system explanations. Onboarding, AI walkthroughs, feature education.
Ambient patterns
Light visual texture. Dashboard zones, AI cards, promo modules, welcome screens.

1. Spot illustrations

Spot illustrations represent one clear concept or outcome.

Use for:

  • Empty states (no devices, no threats, no patches)
  • Patch completed
  • Threat resolved
  • Policy not assigned
  • Missing agent
  • Upgrade available
  • Success celebrations

Rules

  • Must represent one idea only
  • Use centered compositions
  • Keep conceptual metaphor obvious
  • Support adjacent copy
  • Never replace core message text

Examples

+ Protected endpoint No managed devices Successful rollout

2. Low-fidelity workflow UI

Use low-fi UI illustrations for complex system explanations. Avoid real screen-within-screen screenshots in product.

Use for:

  • Guided onboarding
  • AI remediation walkthroughs
  • Spotlight tours
  • Feature education
  • Multi-step deployment explanation
  • Automation flow previews
  • Tree navigation tutorials

Rules

  • Use neutral gray UI blocks
  • Sharp corners for structural clarity
  • Simplified component shapes
  • No realistic screenshots
  • No exact UI replication
  • Highlight only the learning concept

3. Ambient patterns

Ambient patterns add light visual texture without introducing new meaning.

Use for:

  • Empty dashboard zones
  • AI recommendation cards
  • Upgrade banners
  • Promo modules
  • Workspace welcome screens
  • Module landing pages

Rules

  • Must stay behind content
  • Never compete with text contrast
  • Use subtle neutral or semantic tones
  • No strong directional meaning
  • Use only for large supporting surfaces

Ambient patterns should create brand atmosphere, not workflow confusion.

Visual anatomy

All three examples follow a consistent construction pattern from the UEMS illustration library:

  • Primary document shape -- Rounded rectangle with 1.83px stroke (#75A4FE) as the focal anchor
  • Secondary background layer -- Offset document in darker blue (#4E7FDB) adds depth
  • Content detail -- Gear icons, chart bars, certificate badge communicate the specific context
  • Decorative accents -- Sparkle stars (#5BC1A5), small circles (#E56470), cross marks (#7E90B0) add energy without competing
  • Dashed connection lines -- Subtle flow indicators link elements contextually
  • Action affordance -- Gray circle with white + icon (#7E90B0) signals "create new" as a clear CTA

Illustration principles

1. Use illustration intentionally

Before adding an illustration, ask: Does this improve task clarity?

Good use cases

Explain patch rollback

Clarify empty inventory

Encourage first action

Reduce fear in failure states

Celebrate successful deployment

Bad use cases

Decorative filler in dense tables

Background art in modals

Repeated illustrations inside drawers

Random AI sparkle graphics

Decorative dashboard corners

2. Support the copy, never replace it

Illustrations must reinforce text. The user must still understand the message with the image hidden.

Good

Device + shield illustration beside "All endpoints protected"

Clear headline paired with spot illustration

Written CTA beside visual

Bad

Illustration only with no clear headline

Using illustration as severity indicator

No written CTA beside visual

3. Match operational emotion

Endpoint products include emotionally sensitive moments: malware found, policy failed, remote wipe triggered, deployment success, AI recommendation confidence.

Illustration tone should match the emotional weight.

ToneContextVisual approach
NeutralEmpty statesCalm, minimal, informational
Calm confidenceOnboardingWelcoming, guiding, structured
EncouragingRetry flowsSupportive, forward-looking
ReassuringRecoverySafe, settled, restored
CelebratoryLarge rollout successAchievement, completion, pride

Never use playful visuals for destructive or security-risk workflows.

Endpoint-specific illustration patterns

Empty states

Best use case for spot illustrations. Each must pair: spot illustration + clear headline + single next-step CTA.

  • No devices enrolled
  • No failed patches
  • No active threats
  • No software inventory
  • No compliance violations
AI guidance

Use low-fi workflow UI. Critical for trust in AI-assisted endpoint workflows.

  • "How AI isolates devices"
  • "How auto-remediation works"
  • "What this workflow will change"
Security recovery

Use calm, confidence-building spot illustrations. Avoid danger-red once issue is resolved.

  • Threat neutralized
  • Isolation completed
  • Rollback successful
  • Policy restored
Success moments

Use celebratory spot illustrations sparingly for major milestones.

  • 100% patch rollout
  • All devices compliant
  • Zero critical threats
  • Migration completed

Style system

Prism illustrations must visually align with Zoho Puvi typography, 1.5px icon strokes, rounded interface corners, semantic color tokens, and dark mode surfaces.

Style rules

  • Rounded geometric shapes
  • Clean enterprise-friendly metaphors
  • Minimal scene depth
  • Clear foreground focus
  • Neutral supporting objects
  • Optional semantic accent colors
  • Dark-mode-safe surfaces

Never mix illustration styles across modules.

Accessibility

Illustrations must never carry critical meaning alone.

Rules

  • Always pair with text
  • Decorative visuals must use aria-hidden
  • Informative visuals require alt text
  • Preserve contrast in dark mode
  • Avoid flashing success animations
  • Do not embed text inside illustration art

Illustrations support clarity, not accessibility bypass.

Anti-patterns

Avoid these common enterprise UX failures:

  • Decorative threat illustrations in dense dashboards
  • Screenshot-style UI inside onboarding
  • Different illustration styles per module
  • AI-only purple magic graphics
  • Overly playful malware scenes
  • Dense background patterns behind tables
  • Large illustrations inside confirmation modals
  • Using illustration instead of clear CTA text

Principle

In Prism, illustrations reduce uncertainty.

The right illustration system helps admins understand workflows faster, recover confidently, and trust complex endpoint actions.
